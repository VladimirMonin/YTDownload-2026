# Роли

| Роль | Задача | Provider / model | Запрошенный уровень Pi |
|---|---|---|---|
| Oracle | Исследовать текущий код, выбрать достаточную command-first-архитектуру, записать полный план/контракт; помогать при существенных затруднениях | `openai-codex` / `gpt-6-astra` | `xhigh` (Extra High) |
| Coder | Реализовать согласованный срез, тесты и прикладную документацию, реально выполнить проверки | `openai-codex` / `gpt-6.1-sol` | `max` |
| Reviewer | Независимо проверить готовый код и действующие входы, вернуть обязательные замечания и дать итоговый вердикт | `openai-codex` / `gpt-6.1-sol` | `max` |

Это явное назначение пользователя для этого проекта, не наследование модели Hermes. Фактические model/thinking события проверяются в новых записях native Pi-сессии; одна launch-команда подтверждает намерение, а не исполнение. Если установленный provider преобразует уровень, отдельно записывается фактическое отображение без выдуманного «Max».

Начальная адаптация инструкций и философии предшествует передаче реализации в Pi. После передачи Hermes только ставит задачи, хранит ссылки на сессии/артефакты, управляет владельцами и возвращает замечания. Не читает заново весь код и не исправляет его вместо назначенных агентов. Этот документ принят как проектный порядок работы, не как приёмка всего рефакторинга.

## Рабочий цикл

1. Oracle читает [AGENTS](../AGENTS.md), проектные правила, методы пакета и относящиеся исходники. Разделяет существующее, предлагаемое и проверенное. Пишет `docs/command-first/PLAN.md` и `CONTRACT.md`, включая критерии и остаток. Исходники приложения не меняет.
2. После документации/плана Hermes создаёт отдельную ветку. Coder получает канонический план и один связный проверяемый срез, а не право на произвольную переделку приложения.
3. Coder фиксирует фактические проверки, замораживает байты и освобождает кандидат/ресурсы до review. Не stage/commit/push. Reviewer работает в отдельной истории, не принимает авторский PASS за свой; до технического verdict исходники, tests/scripts и index read-only.
4. Замечания возвращаются тому же Coder; исправленный кандидат — тому же Reviewer. Существенная неясность или повторный безрезультатный ремонт — к тому же Oracle с оригинальными требованиями и реальными отказами.
5. Проверяющий сообщает ACCEPTED/NEEDS_CHANGES/ORACLE_REQUIRED для точного среза, exits, NOT_RUN и ограничения. Обязательный новый провал не становится ACCEPTED из-за авторского PASS. При отказе требуемые source/test-исправления через Hermes возвращаются тому же Coder.
6. После ACCEPTED **тот же Reviewer** завершает затронутые документы/инструкции и проверки их final bytes, затем является единственным владельцем index/commit/push. Разрешение действует для принятых срезов command-first в `refactor/command-first`, без нового человеческого согласования каждого commit. Явные пути/при необходимости hunks, проверка index/path set/content/parent; без `git add -A`, stash/reset/rewrite и посторонних изменений.
7. Push только принятых commits в существующий project remote с явным `HEAD:refs/heads/refactor/command-first`, без tags/force/main/release и изменения remote/visibility. До записи проверить destination/outgoing history и применимые CI/branch policies, после — exact remote SHA. Неопределённый ответ требует readback, не слепого retry. Acceptance, local commit, push/readback и remote CI различать; auth wall — delivery blocker, не разрешение извлекать credentials и не запрет следующего независимо разрешённого coding-среза.

Не запускаем двух писателей одних файлов. Разные роли имеют постоянные UUID и пути native session JSONL; для продолжения используется `--session <проверенный существующий файл>`, а не новая беседа с тем же именем. Сессии и полные журналы Pi остаются в обычном домашнем хранилище Pi, не включаются в Git.

## Использование установленного Pi

На начало работы проверен Pi `1.3.0`. Используются существующие вход и авторизация `openai-codex`; credentials не извлекаются и не копируются. Глобальные настройки, extensions и профили не меняются. Не устанавливаем дополнительную агентную платформу.

Из корня проекта для Oracle:

```bash
pi --provider openai-codex --model gpt-6-astra --thinking xhigh --no-skills --skill tools/project-foundation/skills/pf-plan/SKILL.md --skill tools/project-foundation/skills/pf-command-first/SKILL.md
```

Для Coder/Reviewer — та же установленная программа, но отдельные беседы и `--model gpt-6.1-sol --thinking max`. Это пример настройки маршрута, не автоматическая выдача роли или прав. Полное задание передаётся через `@<brief.md>`; для контролируемого запуска `--no-context-files` допустим только с явным чтением корневого AGENTS и сохранением домашних защитных ограничений.

Исполнители используют доступные Serena, codebase-memory и ast-grep по необходимости, не запускают все анализаторы ради галочки; перед выводом об отсутствии символа проверяют корень и актуальность индекса. Эти же границы передают внутренним читателям. Внешний поиск не заменяет текущие исходники; разрешение на работу не разрешает чтение исключённых данных или отправку секретов.

## Неприкосновенные границы

Без изменения GUI-дизайна, удаления пользовательских файлов, запуска реальных YouTube-загрузок, установки/обновления зависимостей или выпуска. Единственное Git-исключение — описанная выше selective доставка уже принятого среза тем же Reviewer; иных прав этот порядок не даёт. Проверки используют временные синтетические данные; для реальной загрузки нужен отдельный конкретный URL и разрешение. Нельзя отключать guards/approvals ради запуска.
